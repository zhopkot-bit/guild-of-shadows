## Исправления

### Последовательная запись в облако

В исходном адаптере два `flush()` могли одновременно вызвать `setData`.
Если старый запрос завершался после нового, в имитации облака оставался старый снимок,
а очередь уже считалась пустой. Этот сценарий воспроизведён до исправления.

Теперь одновременно выполняется только один запрос. Пока он идёт, новые снимки объединяются
в последний; локальная копия пишется сразу. `flush()` во время отправки ожидает также отправку
нового снимка. Обычные отправки сохраняют интервал 15 секунд. После ошибки последний снимок
остаётся в очереди, и попытка повторяется автоматически с тем же ограничением частоты.
Без доступа к игроку SDK игра продолжает сохраняться локально, не создавая лишние таймеры.

Файлы: `src/platform/yandex.ts`, `tests/yandex.test.ts`.

### Общая пауза

`GamePause` учитывает причины независимо: платформу, скрытие вкладки и блокирующее окно.
Платформенный адаптер отдельно объединяет сигнал SDK и собственный показ рекламы.
Снятие одной причины не снимает остальные. Начальное состояние платформы и вкладки
учитывается ещё до запуска боя.

На паузе останавливаются экономический tick, анимация боя, переходы ходов и звук.
Управление боем становится неактивным; горячие клавиши и «Досчитать» не обходят паузу.
Окно офлайн-дохода теперь также удерживает восстановленный бой.
При продолжении звуковой контекст возобновляется без создания нового.
Ожидающий ход отменяется при закрытии экрана; поздний callback старой анимации
не применяет удар и не сохраняет старый бой.

`GameplayAPI.start/stop` управляются в одном месте: учитываются текущая вкладка,
активный забег и пауза. Восстановленный забег учитывается, а `start` вызывается
после `LoadingAPI.ready`. Экран героя тоже учитывает платформенную паузу.

Файлы: `src/ui/pause.ts`, `src/ui/app.ts`, `src/ui/ctx.ts`, `src/ui/battleView.ts`,
`src/ui/squad.ts`, `src/ui/expedition.ts`, `src/ui/sfx.ts`, `src/platform/local.ts`.

### Реклама

Повторный запрос ролика во время показа отклоняется без награды.
Собственная пауза снимается при закрытии, ошибке, исключении и таймауте;
при этом сигнал паузы SDK остаётся независимым. Награда разрешается только
после `onRewarded`; один `onClose` награду не даёт. Повторные и запоздалые
callbacks не завершают один запрос повторно.

## Проверки

### Размер боевого экрана

При замере обнаружена лишняя вертикальная прокрутка на 1920×1080 (7 px).
Высота арены рассчитывалась из фиксированных 52 px для шапки, хотя её фактическая
высота могла быть больше. Теперь шапка и основная часть распределяют высоту viewport
через flex; бой занимает оставшееся место. Высота шапки больше не вычитается константой.
На всех пяти поддерживаемых разрешениях после исправления измерена нулевая прокрутка
страницы, док остаётся внутри viewport. Файл: `src/ui/style.css`.

Среда локальной проверки: Node.js 24.19.0, Chromium, программный WebGL SwiftShader.

| Проверка | Результат |
|---|---|
| `npm run typecheck` | Без ошибок |
| `npm test` | 149 тестов, 15 файлов; добавлены 18 проверок адаптера и 4 проверки паузы |
| `npm run build` | Успешно; JS 180,36 КБ / gzip 66,22 КБ, CSS 42,02 КБ |
| Основной арт-реестр, `--strict` | Без ошибок и предупреждений |
| `npm run sim` | Успешно; обучающие забеги уровня 1: 100%, 98%, 52% побед |
| Полный игровой цикл, 1920×1080 и 667×375 | Ручные действия, reload боя, обе фазы босса, досчёт босса после II фазы, reload итогов, возврат в гильдию; без замечаний |
| Пауза SDK и офлайн-окна | WebGL и Canvas 2D на 1920×1080 и 667×375; без ошибок JS и загрузки ресурсов |
| Размещение боя | 1920×1080, 1366×768, 1024×768, 844×390, 667×375: нет прокрутки страницы, док помещается |

В `tools/qa/platform.mjs` проверяется настоящая production-сборка с имитацией SDK:
начальная пауза, наложение причин, реальные действия через интерфейс, остановка и
возобновление Web Audio, запрет «Досчитать» на паузе, остановка и продолжение автобоя.
Состояние правил боя сравнивается до и после паузы. Проверяются также быстрые повторные
сигналы pause/resume и уничтожение экрана во время приостановленного действия.

Машиночитаемые результаты сохранены в `qa/runtime-2026-11-04/`: два отчёта платформы,
два отчёта сквозного цикла, измерения пяти разрешений и вывод симуляции.

В `tools/qa/e2e.mjs` усилены условия успешного завершения: восстановление HP/раунда/хода,
однократный учёт экспедиции после reload итогов и обязательный возврат в гильдию.
При обнаружении замечаний скрипт возвращает ненулевой код; браузер закрывается и при исключении.
`layout-probe.mjs` теперь учитывает `CHROME`, как указано в инструкции запуска,
и возвращает ошибку при выходе боевого экрана за viewport.

В полном прогоне на программном WebGL при 1920×1080 автобой достиг II фазы босса,
но не завершился за лимит сценария. Для воспроизводимой проверки остального цикла
предусмотрен явный `QA_FINISH_BOSS=1`: после наблюдаемого перехода во II фазу
нажимается штатная кнопка «Досчитать». Такой результат не означает, что полное
прохождение босса только автобоем на 1920×1080 прошло проверку производительности.

## Воспроизведение

```bash
npm run typecheck
npm test
npm run build
node tools/art/validate_pack.mjs public/art/v17/art-pack.json --strict
npm run sim
QA_PARTY=mira,rook,nora npm run qa:saves
npm run preview -- --host 127.0.0.1 --port 4173 --strictPort
```

В другом терминале:

```bash
CHROME=/usr/bin/chromium npm run qa:platform
NO_WEBGL=1 CHROME=/usr/bin/chromium npm run qa:platform -- http://127.0.0.1:4173/ qa-saves/battle.json qa-out/platform-canvas2d
CHROME=/usr/bin/chromium node tools/qa/e2e.mjs http://127.0.0.1:4173/ qa-out/e2e-667x375 667 375
QA_FINISH_BOSS=1 CHROME=/usr/bin/chromium node tools/qa/e2e.mjs http://127.0.0.1:4173/ qa-out/e2e-1920x1080 1920 1080
```

`sim` и `qa:saves` запускаются через `node --import tsx`: это не требует IPC-сокета
CLI `tsx`, запрещённого в текущей изолированной среде.

## Автоматизация

В `.github/workflows/checks.yml` добавлены проверки типов, всех тестов, production-сборки,
основного арт-реестра и симуляции. Отдельная матрица запускает браузерную проверку
платформы на WebGL и Canvas 2D. В WebGL-задании также запускается сквозной цикл
667×375 с явным досчётом босса после II фазы. Отчёты и скриншоты сохраняются в артефакты workflow.
CI настроен на Node.js 22. Workflow проверен локально как YAML; запуск на GitHub
в рамках этой работы не выполнялся.

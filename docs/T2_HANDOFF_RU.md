## Как продолжить

Подключите репозиторий и ветку передачи в новом чате. Для локального checkout:

```bash
git fetch origin refs/heads/t2/runtime-handoff-2026-11-09:refs/remotes/origin/t2/runtime-handoff-2026-11-09
git switch t2/runtime-handoff-2026-11-09
git status --short
```

Явная загрузка ветки работает и в среде Codex, где fetch может быть настроен только на `main`.

В новом клоне ветка должна содержать коммит передачи и быть чистой. В существующей
рабочей копии сначала сохраните её собственные изменения. Состояние удалённой основной
ветки могло измениться: перед интеграцией сравните её с веткой T2 и проверьте пересечения.

Готовый текст для нового чата:

> Продолжаем работу команды T2 над «Гильдией Теней». Используй ветку
> `t2/runtime-handoff-2026-11-09`. Прочитай `AGENTS.md` и `docs/T2_HANDOFF_RU.md`,
> проверь фактическое состояние репозитория и продолжи с ближайшего незавершённого
> этапа. Главный приоритет — качество и сохранность прогресса игрока.

## Выполнено

Первый пакет:

- Облачные записи выполняются последовательно; новые снимки объединяются в последний.
- Ошибки записи оставляют снимок в очереди и вызывают повтор с интервалом 15 секунд.
- Общая пауза объединяет SDK, рекламу, скрытие вкладки и блокирующие окна.
- На паузе остановлены бой и звук; закрытый экран не применяет поздний удар.
- Исправлена лишняя прокрутка боевого экрана; док помещается на пяти альбомных разрешениях.
- Добавлены модульные и браузерные проверки, конфигурация GitHub Actions.

Второй пакет:

- Ограничено ожидание скачивания SDK, инициализации, получения игрока и чтения облака.
- Ошибка загрузки предлагает повтор; непрочитанное облако не заменяется новой игрой.
- При исправной локальной копии предлагается продолжение на устройстве или повтор подключения.
- До выбора локальной игры исходный JSON и `lastSeen` сохраняются без изменений.
- В локальном режиме облачная запись закрыта до успешного чтения в следующей сессии.
- `build:yandex` создаёт `dist-yandex/` с обязательным SDK; обычный `build` создаёт `dist/`.
- Проверена выдача рекламной награды один раз и сохранность флага `doubled` после reload.

Подробности: `RUNTIME_STABILIZATION_RU.md`, `PLATFORM_RELIABILITY_RU.md`,
`../BUILD_AND_CHECK_RU.md`.

## Проверки и их границы

09.11.2026 при подготовке передачи повторно успешно пройдены типизация,
167 тестов в 16 файлах и обе сборки.
Отчёты браузерной приёмки от 04.11.2026 находятся в:

- `qa/runtime-2026-11-04/`: первичная стабилизация, пять разрешений, два сквозных прогона;
- `qa/reliability-2026-11-04/`: 20 сценариев надёжности, восемь сценариев паузы,
  сквозной прогон 667×375 и контрольные суммы сборок той приёмки.

В части сквозных прогонов после достижения II фазы босс завершался штатной кнопкой
«Досчитать». Полное прохождение босса только автобоем на программном WebGL при
1920×1080 не подтверждено: один такой прогон исчерпал лимит сценария.

Во всех указанных проверках SDK и рекламные callbacks имитировались.
Настоящие SDK, облачные сохранения, рекламные показы и физические телефоны
пока не прошли приёмку. Статус GitHub Actions следует проверять по конкретному
коммиту; локальные отчёты не подтверждают запуск workflow на GitHub.

## Инварианты, которые нужно сохранить

1. Не допускать одновременных `setData`. Таймаут записи не даёт права запустить
   следующую запись: предыдущая всё ещё может завершиться на сервере.
2. Не отправлять данные в облако, пока его копия не прочитана успешно.
3. Не перезаписывать сохранение более новой версии.
4. Снятие одной причины паузы не снимает остальные.
5. Отменять ожидающие действия уничтоженного боевого экрана.
6. Принятые рисунки Миры, канонический ростер и текущий баланс в этих пакетах не менялись.

## Ближайшие незавершённые действия

1. Подготовить черновик Яндекс Игр из содержимого `dist-yandex/`, получить доступную
   ссылку на него и провести реальную SDK-приёмку. В этой среде ссылка и доступ
   к черновику пока не предоставлены.
2. Проверить рекламу с наградой, закрытие без награды, ошибки сети, паузу и возврат в игру.
3. Проверить облачный прогресс между двумя устройствами, включая устаревшую локальную
   копию, временную недоступность облака и повтор подключения.
4. Измерить время кадра, загрузку и память на реальных телефонах.
5. Интегрировать ветку T2 с актуальной основной веткой после проверки пересечений
   с работами других команд и CI. Не считать ветку передачи уже слитой.

## Команды

```bash
npm ci
npm run typecheck
npm test
npm run build
npm run build:yandex
node tools/art/validate_pack.mjs public/art/v17/art-pack.json --strict
npm run sim

npm run qa:saves
```

Два preview-сервера в отдельных терминалах:

```bash
npm run preview -- --host 127.0.0.1 --port 4173 --strictPort
npm run preview -- --host 127.0.0.1 --port 4174 --strictPort --outDir dist-yandex
```

Затем:

```bash
CHROME=/usr/bin/chromium npm run qa:reliability -- http://127.0.0.1:4173/ qa-saves qa-out/reliability http://127.0.0.1:4174/
```

Для проверок боевой паузы и поз Миры нужен отдельный набор сейвов:

```bash
QA_PARTY=mira,rook,nora node --import tsx tools/qa/make-saves.ts qa-saves/mira
CHROME=/usr/bin/chromium npm run qa:platform -- http://127.0.0.1:4173/ qa-saves/mira/battle.json qa-out/platform
NO_WEBGL=1 CHROME=/usr/bin/chromium npm run qa:platform -- http://127.0.0.1:4173/ qa-saves/mira/battle.json qa-out/platform-canvas2d
```

# P-01. Проверка запуска в черновике Яндекс Игр

Задача команды — [T4 №21](https://github.com/zhopkot-bit/guild-of-shadows/issues/21). Для проверки нужен URL игры, открытой из черновика в консоли разработчика. В консоли откройте поле «Архив» и выберите «Открыть черновик с debug-панелью». [Режим черновика](https://yandex.ru/dev/games/doc/ru/console/draft-mode) · [Индикаторы debug-панели](https://yandex.ru/dev/games/doc/ru/console/debug-panel).

Выберите тестового игрока. Для первого сценария стенд открывает новый гостевой контекст Chromium.

```bash
npm run build
CHROME=/usr/bin/chromium node tools/qa/yandex-draft.mjs "$DRAFT_URL" qa-out/t4-p01/startup.json dist
```

В черновик должен быть загружен тот же каталог `dist`, который передан последним аргументом. Стенд слушает событие `gos:analytics` с начала загрузки, в том числе в дочерних кадрах. В кадре игры он сверяет SHA-256 загруженного игрового модуля с локальным файлом, проверяет HTTP-ответ на `/sdk.js`, наличие `YaGames.init`, событие `game_start` от адаптера `yandex` и появление игрового интерфейса. При расхождении команда возвращает ненулевой код. Подставлять скрипты или перехватывать ответы для прогона не требуется.

| Сценарий | Что сделать в черновике | Как определить результат |
|---|---|---|
| Инициализация | Открыть тестовую ссылку командой выше | В отчёте `startupObserved: true`, хеши совпадают |
| Готовность | Запустить игру с отладочной панелью SDK | Наблюдается вызов `LoadingAPI.ready()` после появления доступного интерфейса |
| Начало и завершение экспедиции | Начать забег, завершить его, открыть итоги | Панель регистрирует `GameplayAPI.start()` и `stop()` в соответствующие моменты |
| Пауза и звук | Включить звук, запустить автобой, вызвать штатную паузу площадки. Во время паузы скрыть и вернуть вкладку | До снятия обеих причин паузы HP и ход сохраняются, звук и управление приостановлены. После возврата игра продолжает тот же бой |
| Ошибка и ожидание SDK | В отдельном тестовом сеансе проверить ошибку загрузки и задержку ответа, затем восстановить соединение | Записать время и поведение интерфейса, выбранный адаптер, влияние на прогресс. Решение о допустимости локального режима для площадки фиксирует ответственный за выпуск |

Для каждого проведённого сценария запишите время, браузер, ожидаемое и наблюдаемое поведение, приложите отчёт или снимок панели. Успешный запуск даёт результат только для первой строки. Ссылку с параметрами доступа и данные игрока в отчёт включать не нужно.

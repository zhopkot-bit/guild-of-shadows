# Шаблон задания исполнителю

Скопировать в отдельную задачу/рабочую сессию, заполнить поля. План не запускает исполнителя автоматически.

```text
Репозиторий: zhopkot-bit/guild-of-shadows.
Команда: <T1…T6>, GitHub issue: <ссылка из GITHUB_ISSUES.json>.
Пакет: <один ID G/U/A/P/Q/R из WORK_PACKAGES.json>.
Основной разработчик ведёт общую архитектуру и интеграцию.

Перед работой:
1. Прочитать docs/RELEASE_ARCHITECTURE_RU.md и docs/release/TEAM_HANDOFF_RU.md.
2. Проверить актуальные инструкции репозитория и комментарии задачи.
3. Проверить зависимости пакета; записать базовый commit SHA.
4. Создать отдельную ветку от указанной в передаче базы.

Цель: <один проверяемый результат пакета>.
Разрешённая область изменений: <пути команды и согласованные общие файлы>.
Входные материалы: <ТЗ, исходники, API, предыдущий отчёт>.
Зависимости: <ID и их проверенный результат>.
Критерии готовности: <конкретные сценарии/артефакты из пакета>.

Выполнить реализацию, применимые проверки и открыть PR со ссылкой на issue
и ID пакета. Передать основной команде результат, diff, проверенный SHA,
команды воспроизведения, артефакты и оставшиеся блокировки.

Общие реестры, схема сейва и интерфейс Platform меняются по правилам
владения файлами. Не изменять канон/механику и не расширять объём выпуска
без согласованного решения. Не включать посторонние правки.
При недоступном устройстве/SDK/браузере записать точное ограничение;
не отмечать непроведённую проверку как успешную.
Объединение PR и публикацию выполняет основной интегратор после приёмки.
```

Минимальная сдача: ссылка на PR, результат относительно критериев, список выполненных проверок с итогом, оставшиеся блокеры. Формулировка «готово» без проверяемого результата не переводит пакет в `verified`.

# Порядок запуска и работы команд

04.11.2026: пользователь подтвердил готовность исполнителей и разрешил начинать работу. Первая волна разрешена к старту. Это разрешение на выполнение пакетов; фактический старт и результат каждого пакета исполнитель фиксирует в своей GitHub-задаче.

## Начать сейчас

Все шесть команд начинают параллельно. До правок каждый исполнитель записывает в задаче своё имя/логин, ID выбранного пакета, ветку и базовый SHA. Отсутствие назначенного GitHub-assignee не блокирует старт; один пакет одновременно берёт один ответственный. Основной разработчик координирует пересечения.

| Команда / задача | Пакеты к старту | Первый проверяемый результат |
|---|---|---|
| [T1 — игровой цикл, №18](https://github.com/zhopkot-bit/guild-of-shadows/issues/18) | G-01 | Состав первого выпуска и матрица действующих правил; спорные решения выделены владельцу |
| [T2 — интерфейс и рендерер, №19](https://github.com/zhopkot-bit/guild-of-shadows/issues/19) | U-01 | Повторная проверка исправленного короля: обе фазы, 1920×1080 и 667×375, статичные позы и движение |
| [T3 — арт и звук, №20](https://github.com/zhopkot-bit/guild-of-shadows/issues/20) | A-01, A-02, A-03 | Интеграционный пакет принятого Брана, решения по ограничениям рисунков и комплект слоёв арены |
| [T4 — платформа, №21](https://github.com/zhopkot-bit/guild-of-shadows/issues/21) | P-01 | Стенд SDK/lifecycle и проверка запуска, паузы и возврата; результаты черновика платформы либо точный блокер доступа |
| [T5 — QA, №22](https://github.com/zhopkot-bit/guild-of-shadows/issues/22) | Q-01 | Матрица требований/проверок, выбранные устройства, baseline и список дефектов |
| [T6 — интеграция и выпуск, №23](https://github.com/zhopkot-bit/guild-of-shadows/issues/23) | R-01, R-02 | Актуальная база, правила интеграции и CI для тестов, сборки и реестра ассетов |

T3 выполняет три стартовых пакета своими доступными силами; наличие нескольких пакетов не требует трёх исполнителей. Основной разработчик/T6 принимает общий реестр и интегрирует результаты остальных команд. Другие команды не ждут завершения всей художественной работы для независимых задач.

Для U-01 требуется работоспособный браузерный стенд, для реального P-01 — черновик Яндекс Игр. Если доступ отсутствует, исполнитель фиксирует точную причину и требуемый доступ в своей задаче и продолжает независимую подготовку. Непроведённая проверка не отмечается успешной.

## Последовательность результатов

Волны задают порядок получения результатов. Переход конкретного пакета определяется его `depends_on` в [WORK_PACKAGES.json](WORK_PACKAGES.json): не нужно ждать все пакеты предыдущей волны, если нужные входные материалы уже проверены. Наличие блокера запрещает объявлять соответствующий результат принятым, но не останавливает независимые команды.

| Волна | Пакеты | Результат |
|---|---|---|
| 0 — исходное состояние и старт | G-01; U-01; A-01/A-02/A-03; P-01; Q-01; R-01/R-02 | Согласованный объём, проверяемая база, известные блокеры и подготовка необходимых ресурсов/стендов |
| 1 — законченный игровой цикл | G-02/G-04; U-02/U-03; P-02 | Новая игра → отряд → экспедиция → босс I/II → награды → перезагрузка → продолжение |
| 2 — качество и платформа | G-03; U-04/U-05; A-04/A-05; P-03/P-04/P-05; Q-03/Q-04 | Контент, адаптация, звук, реклама, аналитика, SDK и реальные устройства соответствуют критериям |
| 3 — стабилизация релизного кандидата | Q-02/Q-05; R-03/R-04; исправления командами-владельцами | Полный регресс и доказательства на одном commit; нет блокирующих/критических дефектов; проверен пакет и откат |
| 4 — выпуск | R-05 | Решение владельца, модерация, публикация проверенной сборки и проверка после выпуска |

В стабилизации новые функции не добавляются. Команды исправляют обнаруженные дефекты, T5 проверяет исправления, T6 собирает новый кандидат и фиксирует его SHA. Срок выпуска определяется после оценки задач исполнителями и прохождения приёмки.

## Рабочий цикл каждого пакета

1. Исполнитель выбирает пакет, проверяет зависимости и заявляет начало в задаче команды.
2. Создаёт отдельную ветку от базы из [инструкции передачи](TEAM_HANDOFF_RU.md). Для U-01 используется актуальная `art/remaining-art-v2`, а не неполный набор из `main`.
3. Реализует результат в своей области. Общие файлы и интерфейсы согласует с владельцами до пересекающихся правок.
4. Выполняет применимые проверки и открывает PR со ссылкой на задачу команды и ID пакета.
5. Передаёт основному разработчику: что сделано, базовый/проверенный SHA, команды проверки, результаты, артефакты и оставшиеся блокеры.
6. Основной разработчик проверяет архитектуру и diff; T5 подтверждает применимые сценарии. Интегратор объединяет прошедший приёмку PR, обновляет baseline и статус пакета.

Статусы: `ready` → `in progress` → `review` → `verified` → `done`. При препятствии фиксируются `blocked`, причина и следующий ответственный шаг. Статусы и чекбоксы задач отражают реальный результат; разрешение на старт не переводит все пакеты в `in progress` и не закрывает существующие дефекты.

## Канал координации

[Общая задача №17](https://github.com/zhopkot-bit/guild-of-shadows/issues/17) связывает шесть задач команд. В задаче команды исполнитель фиксирует старт, передачу результата и блокировки; в PR — проверяемое изменение. Основной разработчик ведёт общие решения и зависимости. Дублировать пакет в нескольких ветках без согласования не следует.

Контракты, критерии выпуска и ограничения: [архитектура](../RELEASE_ARCHITECTURE_RU.md), [передача](TEAM_HANDOFF_RU.md), [шаблон задания](TASK_BRIEF_TEMPLATE_RU.md).

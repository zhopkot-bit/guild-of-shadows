# Отчёт: пилот Брана, набор цельных поз

27.10.2026. Основа — `main` на `bd05d79`, ТЗ 2.0. Работа ведётся отдельно в `art/bran-poses-v2`. Игровой код, реестр, портрет и основная ветка не изменены.

## Сделано

- Опорный лист из канонического спрайта, портрета и группового арта.
- Семь цельных поз: idle, windup, strike, cast, hit, down, victory. Поза down — на одном колене, с опорой на щит.
- Замах переработан ради более явного скручивания и переноса веса; победная поза переработана в сдержанный салют с эфесом у груди.
- Лист согласованности и отдельное крупное сопоставление стойки, замаха и удара. HTML и скрипт компоновки сохранены рядом с PNG листов.
- Все исходные PNG, первые варианты замаха/победы и запросы к генератору сохранены. Инструмент — OpenAI image_gen; живописная ручная ретушь не выполнена.

## Художественная оценка

Образ ближе к каноническому цельному спрайту: сохранились борода, короткие волосы, массивные округлые наплечники, синий шарф, щит с золотым крестом и длинный меч. Это оценка направления, не утверждение заказчиком.

| Поза | Наблюдение |
|---|---|
| idle | Устойчивая асимметричная стойка, оружие читается. Лицо мягче/моложе канонического портрета, волосы пышнее |
| windup | Вторая версия сильнее скручивает тело и переносит вес назад. Меч всё ещё направлен вверх-вперёд; степень замаха требует оценки |
| strike | Выпад и диагональная доводка читаются, ткань отстаёт. Щит остаётся впереди сильнее, чем описано в ТЗ |
| cast | Щит поднят, лицо остаётся видно, защитное действие отличается от атаки |
| hit | Видны боль, отклонение головы/корпуса и согнутые колени |
| down | Компактная поза раненого с опорой на щит; направление соответствует новому ТЗ |
| victory | Эфес опущен к груди, меч полностью виден. Масштаб фигуры всё ещё отличается; на листе показана поправка ×1,09 |

Между позами меняются мелкие пряжки, кожаные детали, рисунок потёртостей и золота, геометрия щита. Лица в серии похожи, но точного совпадения с каноном не достигнуто. При крупных изображениях нужно дополнительно проверять пальцы, хват и золотой крест. По визуальному осмотру явных дополнительных рук/мечей/щитов и обрезанных предметов нет; это не заменяет окончательную ретушь.

## Техническая проверка

| Проверка | Результат и граница вывода |
|---|---|
| Семь PNG читаются, имеют настоящий альфа-канал | PASS: RGBA, диапазон альфы 0–255; размеры, границы и SHA-256 — `measurements.json` |
| Нативный размер | 1086×1448 у всех семи; **не выполнено требование мастера высотой 2048 px** |
| Размер фигуры idle | 90,26% холста вместо требуемых 75–85%; требуется другой запас на холсте |
| Линия ступней исходников | **FAIL для windup и strike**: 98,7% и 93,2% высоты против pivot 96,0%; сборщик предупреждает, PNG-валидатор обнаруживает ошибки |
| Пробная сборка в `qa-out` | PASS: семь WebP 576×768, суммарно 733 KiB; отдельные изображения 79–125 KiB |
| Строгий валидатор WebP-пакета | PASS, 0 ошибок/предупреждений. Он прямо сообщает, что линия ступней проверяется только по PNG; этот результат не означает готовности выравнивания |
| Строгий валидатор с подключёнными исходными PNG | FAIL: две ошибки линии ступней и ожидаемое превышение игровых бюджетов исходными PNG. Исходные PNG не предназначены для загрузки в игру |
| Листы в Chromium | Все изображения загружены; просмотрены опорный лист, семь поз и крупное сравнение действия |
| Проверка игровой сцены | Не проводилась для этого набора: он ещё не подключён к игре и не принят художественно |
| PSD/KRA с ручной доводкой | Отсутствует; не заявляется готовым |

Исходники не масштабировались ради заявления о мастерах 2048 px. Листы созданы размещением картинок в HTML и снимком браузера; это презентация. В общей полосе используется один масштаб исходных пикселей и перенос к вручную оценённой опоре, кроме явно обозначенного victory ×1,09. Масштаб тела и опоры в самих PNG ещё нужно унифицировать. Запасы по краям ряда поз малы; см. `measurements.json`.

Результаты валидатора сохранены как `validation.json` (WebP) и `source-validation.json` (PNG). Не следует считать зелёный WebP-отчёт художественной приёмкой или скрывать красный отчёт исходников.

## Дальнейший этап

По ТЗ §3.5 сначала оценивается лист согласованности. После согласования облика и пластики остаются: устранение различий лица/экипировки, ручная доводка, полноценные мастера, общий холст/масштаб/точка опоры, строгая проверка исходников, затем интеграция и раскадровка в живой игре. Остальные персонажи в этой ветке не разрабатывались.

В ТЗ всё ещё указано разрешение 390×844, хотя ранее в разговоре выбрана горизонтальная компоновка. Этот конфликт не разрешался изменением игры в рамках художественного пилота.

## Воспроизведение

```bash
npm ci --cache /tmp/gos-npm-cache --ignore-scripts
CHROME=/usr/bin/chromium node tools/art/build_bran_pose_review.mjs
python3 tools/art/build_poses.py art-sources/poses/bran/proposals qa-out/bran-poses-v2/bran
```

Нормальный npm cache среды оказался недоступен; установка с cache в `/tmp` прошла. Для листов используется временный локальный HTTP-сервер и Chromium. Исходные изображения и игровые файлы скрипт не меняет.

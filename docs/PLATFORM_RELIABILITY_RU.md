# T2: восстановление загрузки и защита облачного прогресса

Дата: 04.11.2026. Продолжение `RUNTIME_STABILIZATION_RU.md`.

## Исправленные сценарии

В исходном коде ожидание `YaGames.init`, `getPlayer` или `getData` могло остаться
незавершённым. При отказе облачного чтения и отсутствии локальной копии запускалась
новая игра; её последующее сохранение могло заменить непрочитанный облачный прогресс.

Теперь ожидание ограничено отдельно для скачивания SDK (3 секунды), его инициализации
(8 секунд), получения игрока и чтения данных (по 5 секунд). Таймеры убираются и при
успехе, и при ошибке. Поздние ответы не подключаются к уже выбранной сессии.
Таймаут к `setData` не применяется: такой запрос может ещё завершиться на сервере,
поэтому запуск следующей записи по таймауту вновь создал бы гонку сохранений.

| Условие | Поведение |
|---|---|
| SDK и облако прочитаны | Обычная игра, последовательная запись в облако |
| Облачное чтение или получение игрока не удалось; локальная копия исправна | Выбор «Продолжить игру» или «Повторить попытку» |
| Выбран локальный режим | Прогресс сохраняется на устройстве; облачная запись закрыта до следующей загрузки |
| Нажат повтор до выбора локальной игры | Исходная локальная копия, включая `lastSeen`, остаётся прежней |
| Облако недоступно, пригодной локальной копии нет | Экран повторной загрузки; новый сейв не создаётся |
| Найден сейв более новой версии | Существующее уведомление; локальная и облачная копии не перезаписываются |
| Инициализация SDK завершилась ошибкой | Экран повторной загрузки; новая локальная игра не создаётся |

Пока облачная копия не прочитана успешно, как обычная отправка, так и `flush()`
не вызывают `setData`. Если игрок выбирает продолжение офлайн, автоматическая запись
локальной копии включается после этого выбора. До выбора или повторной загрузки
старый `lastSeen` не заменяется временем пустого запуска.

При повторе используется полная загрузка страницы: создаётся новая сессия SDK,
заново читаются обе копии и применяется существующее правило выбора сохранения.
Это не слияние независимых веток прогресса с разных устройств.

Файлы: `src/platform/index.ts`, `src/platform/yandex.ts`, `src/platform/timeout.ts`,
`src/platform/platform.ts`, `src/main.ts`, `src/ui/app.ts`, `src/content/ui-text.json`.

## Сборки

```bash
npm run build          # dist/: локальный запуск и SDK, если доступен
npm run build:yandex   # dist-yandex/: SDK обязателен
```

Режим Яндекса задаётся безопасной настройкой `VITE_REQUIRE_YANDEX_SDK=true`
в `.env.yandex`. В архив для площадки следует класть содержимое `dist-yandex/`,
чтобы `index.html` лежал в корне архива. Обычная сборка сохраняет возможность локальной
разработки без SDK. Если игра уже успешно инициализировала Яндекс на том же origin,
отдельный маркер `gos.platform` также запрещает незаметный переход на новую локальную
игру при пропаже SDK. Маркер не изменяет формат `gos.save`.

## Проверки

Среда: Node.js 24.19.0 и Chromium. SDK, сеть и рекламные callbacks имитируются;
отрисовывается настоящая production-сборка, а награды выдаются штатными обработчиками UI.

| Проверка | Объём |
|---|---|
| TypeScript и модульные тесты | 167 тестов / 16 файлов; в этом пакете добавлены 18 проверок |
| Обычная и Яндекс-сборка | Обе собираются; JS 182,25 КБ / gzip 67,07 КБ, CSS 42,15 КБ |
| `qa:reliability` с двумя серверами | 20 браузерных сценариев |
| Пауза после изменений загрузки | WebGL и Canvas 2D, 1920×1080 и 667×375 |
| Сквозной цикл 667×375 | Успешно, включая reload боя и итогов; после II фазы босс завершён штатным досчётом |

Машиночитаемые отчёты и контрольные суммы обеих сборок сохранены в
`qa/reliability-2026-11-04/`. Включены 20 сценариев восстановления и наград,
восемь сценариев паузы и отчёт сквозного цикла.

Браузерные сценарии включают отсутствие и зависание SDK, отказ и зависание получения
игрока и чтения облака, исправный и повреждённый локальный сейв, защиту будущих версий,
возврат к новому облачному прогрессу через кнопку повтора и обе конфигурации сборки.
При неудачном запуске сравнивается полный исходный текст локального сохранения.

Рекламные проверки используют экран итогов, подготовленный настоящими правилами забега:

- двойное нажатие кнопки создаёт один запрос ролика;
- `onRewarded` и закрытие добавляют ровно одну награду;
- закрытие без награды и ошибка SDK золото не добавляют;
- повторные и запоздалые callbacks не добавляют повторную награду;
- перезагрузка итогов сохраняет `doubled` и не возвращает кнопку удвоения;
- локальная имитация ролика также останавливает экономику и выдаёт награду однократно.

`tools/qa/reliability.mjs` и обе сборки добавлены в CI. Запуск workflow на GitHub
в рамках этой работы не выполнялся.

## Воспроизведение

```bash
npm run typecheck
npm test
npm run build
npm run build:yandex
npm run qa:saves
```

В отдельных терминалах:

```bash
npm run preview -- --host 127.0.0.1 --port 4173 --strictPort
npm run preview -- --host 127.0.0.1 --port 4174 --strictPort --outDir dist-yandex
```

Затем:

```bash
CHROME=/usr/bin/chromium npm run qa:reliability -- http://127.0.0.1:4173/ qa-saves qa-out/reliability http://127.0.0.1:4174/
```

Для `qa:platform` с Мирой генерируйте отдельный набор через `QA_PARTY=mira,rook,nora`.
Сейв `summary.json` теперь входит в обычную генерацию `qa:saves`.

## Качество сохранения

- `activeRun` хранится как сериализованная строка внутри обычного `GameState`, поэтому попадает в локальную и облачную копии.
- При восстановлении RNG-объекты создаются заново из снимка внутреннего состояния, включая RNG активного боя.
- Некорректный/несовместимый активный забег отбрасывается, не блокируя загрузку остального сейва.
- Старый `lost` не является необратимым после обновления: нормализация сейва превращает его во временную травму.

## Что не подтверждено

- Полный runtime test suite не выполнен из-за недоступной/неустановленной зависимости `vitest`; вместо него пройдены отдельные runtime smoke-сценарии.
- Smoke-проверка выполнила 40 autoplay-забегов: все завершились, повторный `finishRun` не начислял награды повторно, статусы `lost` не появлялись.
- Отдельный боевой smoke прошёл 40 боёв с боссом и проверил фазовый переход, согласованность телеграфа с cooldown, сохранность глобального каталога навыков и восстановление старого сейва без `bossPhase`.
- Дополнительный runtime smoke подтвердил стартовый ростер, отсутствие списания жетонов, паритет редкости и восстановление RNG активного боя.
- Production build v1.3 не подтверждён из-за повторного тайм-аута установки зависимостей.
- Нет автоматизированного браузерного теста реального reload/restore и нет SDK-интеграционного теста облачных сохранений.
- Фазовая машина босса и текстовый телеграф реализованы; анимации предупреждений и читаемость на устройствах всё ещё требуют плейтеста.
- UI ещё содержит часть legacy-представлений и требует полного прохода по Dark Fantasy UI/UX спецификации.

## Рекомендованный следующий шаг

После установки зависимостей выполнить `npm test`, `npm run sim` и `npm run build`; затем добавить Playwright/browser-level сценарии «перезагрузка во время боя», «перезагрузка на выборе события», «перезагрузка на экране награды», «облачная копия новее локальной» и «повторный callback награды». Только после зелёного прогона и проверки SDK стоит считать реализацию готовой к интеграции с платформой.


## Визуальная интеграция v1.3

- Утверждённый Dark Fantasy concept pack используется как исходник фоновых сцен, карточек построек и портретов.
- В код подключены оптимизированные файлы `public/art/scenes`, `public/art/posts`, `public/art/portraits`; реестр — `ART_ASSET_MANIFEST_RU.md`.
- `src/ui/guild.ts`, `squad.ts`, `expedition.ts`, `portrait.ts`, `battleView.ts` и `style.css` обновлены под арт-направление.
- `tsc -p tsconfig.src.json` после изменений прошёл.
- Новый v1.3 asset-path check подтверждает наличие всех файлов портретов, построек и сцен. Runtime-плейтест UI после интеграции не выполнен.
- Наличие арт-ассетов не заменяет production build: `npm install` снова не завершился по тайм-ауту, `npm test` и `npm run build` не подтверждены.
- Скриншоты и ролик в превью-пакете — постановочные макеты/слайд-шоу, а не реальные browser captures или запись игрового процесса.

Рекомендуемый следующий шаг: установить зависимости в обычном Node.js-окружении, пройти `npm run typecheck`, `npm test`, `npm run sim`, `npm run build`, после чего проверить визуальные компоненты на 320px, 390px, tablet и desktop и записать реальный gameplay capture.

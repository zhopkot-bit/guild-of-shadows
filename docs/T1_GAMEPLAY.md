# T1 — контракт игрового цикла

Актуализировано 04.11.2026. Документ описывает реализованные правила. Старый
`expedition-design.md` сохраняется как история прототипа и не определяет текущую механику.

## Границы T1

Состояние и экономика (`src/core`), боевое ядро (`src/combat`), экспедиции
(`src/expedition`), сохранение переходов в UI, соответствующие тесты и симуляция.
Изменения визуальных ресурсов и компоновки арены — отдельная область. В репозитории
пока нет общего документа с распределением остальных команд.

## Правила

- Четыре канонических героя: Бран, Мира, Рук, Нора; в экспедицию идут три разных
  готовых героя. Начальный состав: Бран, Рук, Нора.
- Экспедиция запускается без жетонов. Старые ticket-поля остаются ради совместимости.
- Шесть слоёв выбора и седьмой слой с боссом. Перед боссом обязательно выбрать
  лечение или защиту от первой спецатаки.
- Ручной режим и автобой используют один движок. Те же действия и RNG дают тот же результат.
- Первые три завершённые экспедиции безопасны. Затем павшие получают временное
  ранение на 30 минут; безвозвратной потери героев в текущем цикле нет.
- Победа открывает следующую глубину, если пройдена максимальная доступная;
  всего глубин три. Пределы уровней героев: 8, 14, 20.
- Итоги дают золото и осколки реликвий; rewarded на итогах удваивает золото один раз.
  Rewarded-воскрешение доступно один раз за забег вне боя и до завершения экспедиции.
- Активный забег сохраняется вместе с обоими RNG, HP, очередью, телеграфами,
  модулями, лимитами и уже применёнными итогами.
- Завершённые узлы считаются по маршруту: сундук после выбора награды, лагерь после
  отдыха/тренировки, событие после продолжения, засада после победы, элита после
  выбора трофея. Босс завершает седьмой узел. Поражение текущий узел не завершает.

## Переходы

| Стадия | Действие | Следующая стадия |
|---|---|---|
| Без забега | Запуск | map |
| map | Вход в обычный/элитный бой | battle |
| map | Вход в событие | event |
| map | Вход в сундук/лагерь | chest / camp |
| map | Вход к боссу | prep |
| event | Выбор исхода | eventResult |
| eventResult | Продолжение | map либо battle при засаде |
| chest | Выбор одной награды | map |
| camp | Отдых либо тренировка | map |
| prep | Лечение либо защита | battle |
| battle | Действие участника | battle, включая окончившийся бой до подтверждения |
| battle | Подтверждение победы | map; после элиты chest; после босса ended |
| battle | Подтверждение поражения | ended |
| map | Подтверждение выхода | ended с поражением |
| ended | Первое открытие итогов | ended, награды применены и закешированы |
| ended | Возврат из итогов | Без забега |

Значимые изменения сохраняются после применения:
запуск, вход в узел, выбор события, продолжение события, сундук, лагерь, подготовка,
действие боя, подтверждение боя, воскрешение, применение итогов, удвоение, закрытие итогов.
Выход из подземелья приводит на экран итогов, где награды применяются и сохраняются.
Вход в узел, выбор и продолжение события, воскрешение сохраняются до перерисовки.
Автосохранение раз в 15 секунд и сохранение при скрытии/закрытии вкладки дополняют
эти точки. `Platform.save` гарантирует постановку в очередь; доступность и подтверждение
облачной записи зависят от платформы.

## Инварианты загрузки

- Party очищается от повторяющихся и несуществующих id до ограничения размера.
  API запуска также не считает одного героя несколькими участниками.
- Глубина — конечное целое число от 1 до максимальной открытой глубины.
- Участников ровно три, id уникальны, для каждого есть корректный снимок Hero.
  Восстановление приложения дополнительно проверяет наличие участников в гильдии.
- HP участников находится в диапазоне 0..1, статус живого согласуется с HP.
- Узлы имеют уникальные id; ссылки ведут на следующий слой. История посещения
  образует допустимый путь и заканчивается текущим узлом.
- Стадия боя содержит валидный бой, его RNG, характеристики, участников, очередь,
  текущего ходящего и пригодные для отображения ссылки журнала.
- Стадии события и его результата содержат необходимые данные. Определение события
  восстанавливается из текущего реестра по id.
- Стадия сундука содержит хотя бы одно корректное предложение.
- Завершение содержит результат. Флаг `finished` требует кеша итогов, поэтому
  перезагрузка не повторяет начисление. Флаг `doubled` сохраняется в кеше итогов.
- Старые роли/враги переводятся миграцией GameState v1 → v2; старые реликвии и
  предложения сундуков преобразуются до проверки актуального состояния.

Формат GameState остаётся v2: новых обязательных сохранённых полей нет.
Необязательное `completedNodes` хранит завершённый префикс маршрута. Активные старые
забеги без этого поля пересчитываются по стадии и посещённому пути; уже завершённые
исторические итоги сохраняют прежние числа и не пересчитывают награды.

## Пауза и платформа

Общий `PauseController` учитывает независимые причины: SDK, скрытая вкладка,
блокирующее окно. Платформенные адаптеры отдельно учитывают открытый рекламный ролик.
Снятие одной причины не возобновляет игру, пока остаётся другая.

Во время паузы останавливаются экономика, сцена, звук и применение боевых действий;
ввод боя блокируется. Режим «Досчитать» проверяет ту же паузу и уступает очередь
событий между действиями. Закрытый View отменяет ожидания; его отложенный удар не
может изменить модель. Окно офлайн-дохода блокирует восстановленный бой до закрытия.

Подписка SDK на pause/resume выполняется до ожидания getPlayer. Рекламные callback
снимают только собственную паузу; таймаут и повторные callback не выдают награду
повторно и не оставляют собственный флаг рекламы включённым. GameplayAPI управляется
общим состоянием приложения и запускается после LoadingAPI.ready.

## Повреждённая экспедиция

Повреждение activeRun не обнуляет гильдию и не выдаёт награду за забег.
До очистки activeRun исходное полное сохранение записывается в localStorage под
`gos_corrupt_run_backup`; игрок видит уведомление и может начать новую экспедицию.
Если браузер не разрешает резервную запись, исходный activeRun сохраняется,
а перезапись локального и облачного сохранения в этой сессии отключается.

   текущее состояние и доказательства описаны в [T1_REVIEW.md](T1_REVIEW.md).

   после измерений и определения целевых длительности и сложности.

Проверки первой итерации: уникальность отряда, некорректные глубины, повреждённые
стадии/карта/бой/RNG, все стадии после сохранения, миграция v1, полный повторный
load итогов без начисления, успешная и неуспешная резервная запись, браузерные
проверки немедленного сохранения после выбора.
